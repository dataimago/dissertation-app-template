# AI agent operating manual

> This repository is an AI-native dissertation environment provisioned by [dissertation.ai](https://dissertation-ai.dataimago.ai), built on the [dataimago](https://github.com/dataimago/dataimago) framework. **Every AI tool reads this file** — Codex, opencode, Cursor, Copilot and others directly; Claude Code through `CLAUDE.md`. The project's own facts (title, author, institution, layout) are in `dataimago-spec.yaml`; read it first.

## What this repo is

A Next.js dissertation environment holding the user's dissertation work — text, methodology, chapter PDFs, AI tooling context.

**Where the thesis book lives is one field of `dataimago-spec.yaml`: `source.quartoHome`** (read by `src/lib/manuscript-home.ts`; never join paths or read `source.case` to find the chapters). "The book folder" below means the folder it gives:
- **`repo: app`** — this repository, at `path` (`thesis/`). Either there is no R package (`source.case: no-r`), or the author connected an R package they already had (`source.rPackage` set): that package is linked as a submodule at `packages/r-packages/<package name>/` and is **never written in**; the chapters cite it. Built by this repo's own `build-thesis.yml` (Quarto + LuaLaTeX, no R: code in a chapter is an inert listing).
- **`repo: package`** — the new R package dissertation.ai created, a Git submodule at `source.rPackage.submodulePath`, at `path` (`ui/www/`: chapters, the house thesis class in `thesis-class/` and the profiles in `profiles/`, the Quarto book); R code in the package's `R/`; built by the package's own `build-thesis.yml`.
- **`repo: referenced`** — the author's existing repository is their whole dissertation (`source.referencedRepo`, `source.rPackage` null): it holds their dissertation, scripts and data and is **referenced, not linked as a submodule**. `/ingest` reads it in place; the working chapters, once imported, live at `thesis/` here.
- **No `source.quartoHome`, or a `source.rPackage.quartoRoot`:** the repository was set up before the dissertation.ai beta and is not supported. Name no folder and do no book work: tell the author the message in `src/copy/predates-beta.txt`.

Read the spec first; the rest of this manual notes the locations where they differ.

**Your first act in a fresh clone is `/ingest`.** It reads whatever the author brought (`raw/`, and `raw/inbox/` if they dropped a folder) and builds the knowledge base in `wiki/`. If `raw/manuscript/LOCKED.md` exists, `/import-manuscript` follows. See `KNOWLEDGE.md`.

**Skills work in any AI tool.** Each procedure is a plain Markdown file at `.claude/skills/<name>/SKILL.md`: `ingest`, `import-manuscript`, `thesis-build`, `thesis-format`, `coordinate`. Claude Code runs them as slash commands (`/ingest`). In any other tool (Codex, opencode, Cursor, ChatGPT with folder access), "run `/ingest`" means: read `.claude/skills/ingest/SKILL.md` and follow it step by step. Agent briefs for specialised roles are in `.claude/agents/`; any tool can read them the same way.

## The dataimago-spec.yaml is the contract

Every field in `dataimago-spec.yaml` affects something downstream. When the user edits the spec + pushes, `generate.yml` runs and regenerates derived files (types, MCP tool definitions, `.ai-context/`, etc.). **Never edit generated files directly without first updating the spec.**

The spec documents itself: each block in `dataimago-spec.yaml` carries a comment saying what it drives, and the README's "Editing your dissertation" table maps common changes to fields.

## When the user asks for help

- **"Edit chapter X"** — `chapters/X.qmd` in the book folder. `build-thesis.yml` rebuilds the PDF on push (the new R package's when the book is in it, this repo's otherwise).
- **"Add a committee member"** — on the house class, add them under `committee:` in the `thesis:` block of the book's `_quarto.yml`, in the book folder `source.quartoHome` names: with `repo: package` that file is in the new R package (the commit is in that package, then the submodule pointer here); otherwise it is in this repo (the commit is here). The PDF takes advisor and committee names from there, not from the spec's `advisors` block, which records the interview's answers. A `vendored` book has no `thesis:` block: the names are set the way its class asks (the `.cls` named by `documentclass` in that `_quarto.yml`); do not add a `thesis:` block. In every case show the author the `git` commands with paths filled in; do not run `git add`, `commit`, `push` or `gh pr create` for them.
- **"Change citation style"** — edit `dataimago-spec.yaml`'s `vertical.dissertation.thesis.bibliography.citationStyle`. Push.
- **"My institution requires a specific thesis format"** — one house class (`dataimago-thesis`, in `thesis-class/` beside the chapters) plus a profile per institution (`profiles/<id>.yaml` and its compiled `<id>.cfg`) does the formatting; `thesis.profile` in the book's `_quarto.yml` selects the profile. `vertical.dissertation.thesis.classFile.type` says where the profile comes from, in the three modes of the thesis-class registry (`dataimago/dissertation-thesis-classes`, `schemaVersion` 2): **`shipped`**, the registry has a profile for the author's institution (an entry of `profiles` with `mode: shipped` and `status: available`, never the `house` profile), and they use it as-is; **`vendored`**, the author provides their institution's own class file (switching a house-class book to it is `thesis-build`, "Switching to `vendored`": the `.cls`/`.sty` go beside `_quarto.yml`, `template-partials`, `filters` and the `thesis:` block are dropped, `documentclass` becomes the `.cls` file name without its extension, `thesis.classFile.type` becomes `vendored` with `path` set to the `.cls` file name beside `_quarto.yml` (extension included), and `_environment`, `thesis-class/` and `profiles/` are removed, all only after the author's yes on that list); **`generated`** (the default), the author starts from the registry's `house` profile and adapts it to their institution's formatting guidelines. The `house` profile is where `generated` starts, not what `shipped` means. For `shipped`, look up `vertical.dissertation.institution.name` in the registry's public `registry.json`, resolve the profile's `class` in `classes`, fetch the class bundle (`path` + `companions`, under `classes/<class>/`) **and** the profile's `cfg` + `yaml` (under `profiles/`) with `python3 <book folder>/thesis-class/sync.py sync --ref main --profile <id>` from the repository root (the book folder), change `profile:` in the `thesis:` block of `_quarto.yml`, then prepare the commit (show the author the `git` commands with paths filled in; do not run `git add`, `commit`, `push` or `gh pr create` for them); if the institution has no profile there, say so plainly and offer `generated`. The steps are in `.claude/skills/thesis-build/SKILL.md` ("Setting up a shipped profile"); `THESIS-CLS-README.md` (in the book folder) explains the modes to the author. `build-thesis.yml` builds from the committed files and never fetches from the registry. A request to build or diagnose the thesis builds from those committed files: it never fetches from the registry, never runs `sync.py sync --ref main`, never edits `profile:` and never starts `thesis-format`; setting up or updating a shipped profile, or adapting a guide, happens only when the author asks (or says yes when offered). Never hand-edit the house class files in `thesis-class/` or a shipped profile (the copies pinned from the registry; an author's own `.cls` in `vendored` mode is theirs, repaired only after a yes); `python3 <book folder>/thesis-class/sync.py check` shows what differs. A book without `thesis-class/` is `vendored` (its own class: build it as it is) or on the `thesis.cls` layout from before the house class, which is not supported (`thesis-build`, "Where things are", **No `thesis-class/`**).
- **"Turn my formatting guide into a profile" / "share my profile with the registry"** — run `/thesis-format` (`.claude/skills/thesis-format/SKILL.md`). It reads the guide in `raw/thesis-formatting/` and fills a profile for the house thesis class field by field, as a new `profiles/<id>.yaml` with `extends: house` (`profiles/house.yaml` is read only as the baseline, never copied in, so no house default is passed off as the guide's): each value cited to the guide's page or section, values read from a sample marked `inferred`, and whatever the guide leaves unstated listed under `unstated` and never guessed. It validates the profile against the registry's schema, builds the registry's synthetic sample book with it, compiles the profile next to the chapters (`profiles/<id>.yaml` and `<id>.cfg`: `profiles/` in the book folder) and gives you a checklist to confirm against the guide; nothing is committed until you do. On the house class, changing `profile:` to `<id>` in the `thesis:` block of `_quarto.yml` then makes the author's own PDF follow it (`thesis-build`). Offering the profile to the registry is a separate, optional step that happens only with your explicit consent: you open a pull request from a fork, and a maintainer re-pushes it to a branch in the registry repository, opens a same-repository pull request that credits you (that one gets the automated review), and closes your fork pull request with a link. The profile holds facts about the guide only: no manuscript content and no real people's names.
- **"How do I add my IRB number?"** — edit `dataimago-spec.yaml`'s `vertical.dissertation.compliance.irb` block. The interview deliberately didn't ask for this; it's an "additional information (fill in over time)" field.
- **Writing prose (chapters, wiki pages, READMEs)** — read `writing/STYLE.md` first and write under it. The spec's `vertical.dissertation.thesis.writingStyle` selects how that file is sourced (shipped / vendored / generated — see `writing/README.md`); the interview deliberately didn't ask.
- **"I want figures in X"** — `vertical.dissertation.graphics.engine` records the preference (`pstricks`, `tikz`, `r-base`, `ggplot2`; default `unspecified` = choose per context). Note: LaTeX-native engines render in the thesis PDF but not on HTML surfaces until converted — prefer R engines for figures that must appear on the knowledge site.

## Working with the author

- **Work on a branch and propose changes as pull requests.** Never push to `main`, merge, delete, or force-push without the author's explicit go-ahead.
- **The writing is the author's scholarship.** Suggest changes and explain them; never silently rewrite their prose. When you draft new text, say that you drafted it.
- **Ask before acting outside this repository** (other repos, services, accounts), and say what you will do first.

## Constraints

- **Don't delete `.ai-context/` if it exists.** It's generated by `dataimago::ai()` for AI tool consumption.
- **`raw/` is read-only for you.** Cite from it, summarize it, link to it, derive analysis from it — but never modify or rewrite a file. The one exception is `/ingest`'s first pass, which *moves* files out of `raw/inbox/` into their category. Your work goes in `wiki/` or in `dataimago-spec.yaml`. See `raw/README.md` and `KNOWLEDGE.md`.
- **`raw/inbox/` and `raw/private/` are gitignored. Never `git add -f` either, and never commit or push on the author's behalf while `raw/inbox/` still holds unsorted material** — history is not undone by a later move to `raw/private/`.
- **Never read `raw/private/`, and never read a data file beyond its header row.** Private material is listed in `raw/MANIFEST.md` so you know it exists; its contents are not yours to see. If `/ingest` set anything aside there, check the repository's visibility before pushing (see below). If it is public or internal, or the check fails, tell the author and show them how to make it private; only a private repository needs no warning. The exact sentences for each result are in `.claude/skills/ingest/SKILL.md`, step 1, and `/ingest` puts one at the top of its report.
- **If `raw/manuscript/LOCKED.md` exists, it governs.** The manuscript beside it is the author's finished dissertation, imported as authoritative v1.0. Extend it — never regenerate, restructure, summarize-and-replace, or "improve" it. The **working copy** you extend is the `.qmd` derivative `/import-manuscript` creates (`chapters/` in the book folder); the files under `raw/manuscript/` are never edited, and where they and anything else disagree, they win. Legitimate work builds on top: derived papers, a revised edition as a new version, new chapters clearly marked post-v1.0. (This is stronger than the `raw/` rule above: that one forbids editing the bytes, this one forbids replacing the work.)
- **Don't hand-edit the knowledge site's synced design files** (`wiki/assets/neutral-*.scss`, `wiki/assets/fonts/`; each text file's first line says "do not edit"). Put a site-specific rule in `wiki/assets/site.scss`; upgrade or opt out as `KNOWLEDGE.md` ("The site's look") describes.
- **Don't commit secrets.** No API keys, no `.env.local`, no institutional credentials.
- **Never put identifiable personal data in git** (participant data, names with addresses, IDs, contact lists). If you find any outside `raw/private/`, stop and tell the author.
- **Check the repository's visibility before pushing** (`gh repo view --json visibility`, or the label beside the repository's name on GitHub). **Public repository + unpublished work = warn first.** If this repository is public and holds unpublished chapters, data, or anything under embargo (see `vertical.dissertation.thesis.embargo` and `compliance.dua` in the spec), tell the author before pushing and show them how to make it private (repository Settings → General → Danger Zone → Change visibility).
- **(R-package layouts) the submodule is a real Git repo.** With `quartoHome.repo: package` (a new R package), changes to chapter content + R code go in the R package's repo, not here — commit there, then commit the updated submodule pointer here. An existing R package linked (`repo: app`) is never written in: its chapters are in `thesis/` here; propose a change to the package itself only when the author asks, as their own commit there. (Content-only layout has no submodule: edit `thesis/` and commit in this repo directly.)
